## 概要

<!--
ガイドライン:
- この機能が現在「どのように動いているか」を簡潔に説明

Go 版 Wikino では、存在しないページや権限のないリソースへのアクセス時にスタイル付きの 404 エラーページを表示する。ルーティングにマッチしなかった場合と、各ハンドラー内で明示的に NotFound を返す場合の両方で、統一されたエラーページが表示される。

エラーページはメンテナンスページと同様のスタンドアロン方式で実装されており、セッション取得や DB アクセスを必要としない。

**目的**:

- ユーザーが存在しないページにアクセスした際に、アプリケーションのデザインに沿ったエラーページを表示し、ユーザー体験を向上させる
- 「トップページに戻る」リンクを提供し、ユーザーの離脱を防ぐ

**背景**:

- Go 標準の `http.NotFound` は素のテキスト（`"404 page not found"`）を返すため、ユーザー体験が悪い
- 404 発生時にはセッションや DB が利用できない可能性があるため、外部依存のないスタンドアロン方式を採用した

## 仕様

### 404 エラーページ

- ルーティングにマッチしなかった場合、スタイル付きの 404 エラーページが表示される
- ハンドラー内で `handler.NotFound(w, r)` が呼ばれた場合も同じエラーページが表示される
- エラーページには以下の要素が含まれる:
  - 絵文字（🫥）による視覚的なインジケーター
  - 「お探しのページは見つかりませんでした」メッセージ
  - 「トップページに戻る」リンク（`/` へ遷移）
- 日本語・英語の両方に対応する（i18n）
- エラーページの表示はセッション取得や DB アクセスを必要としない

### 対象ステータスコード

| ステータスコード          | 対応状況                        |
| ------------------------- | ------------------------------- |
| 404 Not Found             | スタイル付きページ              |
| 503 Service Unavailable   | メンテナンスページ              |
| 500 Internal Server Error | 未対応（スコープ外）            |
| 403 Forbidden             | 未対応（現在は 404 として扱う） |

### ファイル構成

```
go/internal/templates/pages/errors/
├── maintenance.templ        # メンテナンスページ（503）
└── not_found.templ          # 404エラーページテンプレート

go/internal/handler/
└── errors.go                # NotFound ヘルパー関数（全ハンドラーで共用）
```

エラー系テンプレートは `pages/errors/` ディレクトリにまとめて配置している。メンテナンスページも実質的には 503 エラーページであり、同じディレクトリに配置することで統一感を持たせている。

### テンプレート設計

エラーページはレイアウトテンプレートに依存しないスタンドアロンの templ コンポーネントとして実装している。完全な HTML ドキュメントを自身で生成し、CSS はインラインで埋め込んでいる。

スタンドアロン方式を採用する理由:

- 404 発生時にはセッションや DB が利用できない可能性がある
- ログインユーザー情報の取得が不要で、シンプルに保てる
- メンテナンスページの実装パターンと統一感がある

### ヘルパー関数

`go/internal/handler/errors.go` に共通の `NotFound` 関数を定義している。各ハンドラーは `http.NotFound(w, r)` の代わりに `handler.NotFound(w, r)` を呼び出す。

### ルーター設定

chi ルーターの `r.NotFound()` メソッドでグローバルな NotFound ハンドラーを登録している。ルーティングにマッチしなかったリクエストは自動的にこのハンドラーで処理される。

### i18n 翻訳キー

| キー                          | 日本語                                 | 英語                                            |
| ----------------------------- | -------------------------------------- | ----------------------------------------------- |
| `error_not_found_title`       | ページが見つかりませんでした \| Wikino | Page Not Found \| Wikino                        |
| `error_not_found_message`     | お探しのページは見つかりませんでした   | The page you are looking for could not be found |
| `error_not_found_back_to_top` | トップページに戻る                     | Back to top page                                |

### デフォルトレイアウト内でエラーページを表示する

サイドバーやナビゲーションを含むデフォルトレイアウトを使って 404 ページを表示する方針。

**不採用の理由**:

- 404 発生時にセッション情報やサイドバーデータの取得が必要になり、追加の DB アクセスが発生する
- セッションや DB が利用できない場合にエラーページ自体が表示できなくなるリスクがある
- メンテナンスページのスタンドアロン方式と統一感がなくなる

### `http.NotFound` をそのまま使い、ミドルウェアでレスポンスを書き換える

`ResponseWriter` をラップするミドルウェアを作成し、ステータスコード 404 のレスポンスをインターセプトしてエラーページに差し替える方針。

**不採用の理由**:

- `ResponseWriter` のラップは実装が複雑になる（`WriteHeader` と `Write` の順序制御、`Flush` や `Hijack` インターフェースの対応など）
- 各ハンドラーのヘルパー関数置き換えの方がシンプルで明示的
