## 設計改善の提案

### `go/internal/templates/components/draft_page_response.templ` + `draft_saved_time.templ`: 未使用コンポーネントの残存

**ステータス**: 対応済み

**現状**:

`DraftPageShowResponse` テンプレート内で保存時刻の HTML を直接レンダリングしており、既存の `DraftSavedTime` コンポーネントの利用箇所がなくなっている（テストファイルからのみ参照）。

```templ
// draft_page_response.templ - 保存時刻のHTMLを直接記述
if data.HasDraft {
    <div id="page-draft-saved-at" hx-swap-oob="outerHTML" class="text-xs text-right text-muted-foreground">
        @templ.Raw(templates.T(ctx, "page_edit_draft_saved_time", ...))
    </div>
}
```

```templ
// draft_saved_time.templ - 同じHTMLだがhx-swap-oobなし（未使用に）
templ DraftSavedTime(modifiedAt time.Time, timeZone string) {
    <div id="page-draft-saved-at" class="text-xs text-right text-muted-foreground">
        @templ.Raw(templates.T(ctx, "page_edit_draft_saved_time", ...))
    </div>
}
```

**提案**:

`DraftSavedTime` コンポーネントとそのテスト（`draft_saved_time_test.go`）を削除する。OOB スワップでは `hx-swap-oob` 属性が必要なため `DraftSavedTime` をそのまま再利用できず、`DraftPageShowResponse` 内にインラインで記述するのは妥当な判断。ただし、元のコンポーネントが未使用のまま残っている。

`formatTimeInZone` ヘルパー関数は `DraftPageShowResponse` からも利用されているため、`draft_saved_time.templ` から削除する場合は関数の配置先を検討する必要がある（例: `draft_page_response.templ` に移動、または共通ヘルパーに移動）。

**メリット**:

- デッドコードの除去でコードベースの見通しが良くなる
- 同じ HTML 構造が 2 箇所に存在する混乱を防止

**トレードオフ**:

- フェーズ 5（クリーンアップ）で対応する方が、変更の粒度が適切かもしれない
- `formatTimeInZone` の配置先を決める追加作業が発生する
