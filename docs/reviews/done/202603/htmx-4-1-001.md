### レビュー確認事項

各 templ ファイルについて以下を確認しました：

1. **Datastar 属性の完全除去**: 全 7 ファイルで `data-on:submit__passive="$isSubmitting = true"` が `hx-on:submit="disableSubmitButtons(this)"` に正しく置換されている
2. **Datastar ボタン属性の除去**: `data-attr:disabled="$isSubmitting == true"` が全箇所で削除されている（page/edit.templ では 2 箇所のボタンから削除）
3. **CSRF 対策**: すべてのフォームで `<input type="hidden" name="csrf_token">` が維持されている（[@go/docs/security-guide.md#CSRF対策](/workspace/go/docs/security-guide.md)）
4. **自動生成ファイルの整合性**: `_templ.go` ファイルが `.templ` ファイルと一致しており、`disableSubmitButtons` 参照を含み、`isSubmitting` 参照が 0 件
5. **JS 関数の実装**: `disableSubmitButtons` が `window` オブジェクトに正しく割り当てられ、`button[type=submit]` のみを対象としている

## 総合評価

**評価**: Approve

**総評**:

作業計画書タスク 4-1 に記載された全 7 ファイルのフォーム二重送信防止が、Datastar の `$isSubmitting` シグナル方式から htmx の `hx-on:submit` + グローバル関数方式に正しく移行されている。

良かった点：

- 変更が最小限でクリーン。各 templ ファイルの差分は 2 行の変更（`data-on:submit__passive` → `hx-on:submit` の置換 + `data-attr:disabled` の削除）のみ
- 通常の HTML フォーム送信を維持しており、ハンドラー側の変更が不要
- `disableSubmitButtons` 関数が `button[type=submit]` に限定されており、意図しない要素を disabled にしない
- 作業計画書の設計セクション・採用しなかった方針セクションも適切に更新されている
- CSRF 保護が引き続き機能していることを確認済み
