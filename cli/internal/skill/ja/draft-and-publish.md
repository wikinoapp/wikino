# 下書きを書いて公開する手順書

コマンドの一覧は [SKILL.md](SKILL.md) を参照する。
各コマンドの引数と出力の項目は、初めて使う前に `wikino <command> --help` で確かめる。

下書きは、ページを公開せずに書き換えるためのものである。
利用者が「下書きにして」「公開する前に見せて」と頼んだときや、トークンに下書きの権限しか無いときは、ページを直接更新せずに下書きを書く。
トークンのスコープは `wikino auth status` で確かめられる。

## 下書きを作る

- 既存のページの下書きは `wikino draft create <ページ番号>` で作る。本文を渡さなければ、ページの今の内容が下書きになる
- 新しいページの下書きは `wikino draft create --topic <番号> --title <タイトル> --body-file <ファイル>` で作る。出力の `page_number` が新しいページの番号になる
- ページに自分の下書きが既にあると、作成は終了コード6で失敗する。`wikino draft get <ページ番号> --md` で今の下書きを読み、更新する

新しいページの下書きの作成は冪等ではない。
結果が分からないときは、送り直す前に `wikino draft list` で作成済みかを確かめる。

## 下書きを書き換える

書き方 (本文の渡し方・リンクの張り方・`--dry-run` での確認) は、[edit-page.md](edit-page.md) と同じである。
`wikino page` の代わりに `wikino draft` のコマンドを使う。

- 読むのは `wikino draft get <ページ番号> --md`、書き戻すのは `wikino draft update <ページ番号> --md-file <ファイル>`
- 一部だけを変えるときは `wikino draft update <ページ番号> --edits <ファイル>`

下書きはWeb画面の自動保存でも更新される。
利用者がWeb画面で同じ下書きを開いていると、終了コード6で失敗しやすい。
そのときは読み直して変更を反映し直し、何度も続くなら、Web画面での編集を止めてもらうよう利用者に頼む。

## 編集履歴を確かめる

`wikino draft revision list <ページ番号>` で、下書きの作成・更新ごとの記録を新しい順に出す。
過去の内容に戻すときは、`wikino draft revision get <ページ番号> <リビジョンのID> --md` で読んだ本文を、`wikino draft update` に渡す。
リビジョンの `--md` の出力には版が無いため、そのままでは `--md-file` に渡せない。

## 公開する・削除する

公開 (`wikino draft publish`) と削除 (`wikino draft delete`) には、読んだ下書きの版を `--if-match` で渡す。
版は `wikino draft get` の出力の `etag` である。

- 公開すると、下書きの内容でページを上書きし、下書きと編集履歴は消える。下書きを作った後にページが更新されていても、その変更は下書きの内容で上書きされる
- 削除すると、下書きと編集履歴は元に戻せない。ページそのものは残る
- タイトルの無い下書きは公開できない。先に `wikino draft update <ページ番号> --title <タイトル>` でタイトルを付ける

### 確認を求められたら

公開と削除は、`--yes` を付けずに実行すると、何もせずに終了コード9で終わる。
標準出力のJSONには、何が起きるか (`changes`) と、承認後に実行するコマンド (`confirm_command`) が入っている。

1. `changes` の内容を、そのまま利用者に見せる
2. 利用者に承認を求め、返事を待つ
3. 承認されたら、`confirm_command` をそのまま実行する。書き換えたり、別の版を入れたりしない
4. 承認されなかったら、実行しない

自分で `--yes` を付けて確認を省かない。
利用者が前もって「確認せずに公開してよい」と言っていても、`changes` は示してから実行する。

`confirm_command` を実行して終了コード6で失敗したら、確認の後に下書きが更新されている。
読み直して内容を利用者に伝え、もう一度確認を求める。

## 下書きの権限だけを持つトークンで使う

ページの書き込みのスコープ (page:write) を持たないトークンでは、ページの作成・更新と下書きの公開ができない。
既存のページの下書きと新しいページの下書きは作成・更新できる。
この運用では、下書きを書いた後に、下書きのURL (出力の `url`) を利用者に示し、Web画面で確かめて公開してもらう。
